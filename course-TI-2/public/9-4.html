9.4 Graphenfärbbarkeit

Wir verlassen nun zumindest scheinbar das Feld der Komplexitätstheorie und betrachten Graphenalgorithmen. Sie sollten beim Durcharbeiten dieser Kapitel meinen Code herunterladen und damit rumspielen:_reductions.zip

Definition 9.4.1 Sei $G = (V,E)$ ein Graph. Eine $k$-Färbung von $G$ ist eine Funktion $c: V \rightarrow \{1,\dots, k\}$. Die Menge $\{1,\dots, k\}$ bezeichnet man in diesem Zusammenhang als die Farben. Die Färbung heißt gültig (Englisch proper) wenn

$$ \begin{align*} \forall\ \{u,v\} \in E: \ c(u) \ne c(v) \ ? \end{align*} $$

gilt.

Problem 9.4.2 ($k$-Colorability). Gegeben ein Graph $G=(V,E)$, gibt es eine gültige $k$-Färbung $c$?

Eine Anwendung von $k$-Colorability wäre zum Beispiel die Wahl der Sendefrequenzen von 5G-Masten: zwei Masten, deren Sendebereiche sich überlappend, sollten nicht im gleichen Frequenzband senden, da Handys dann beide Masten "hören" könnten und es zu Störungen käme. Andererseits stehen den Netzanbietern nicht beliebig viele Frequenzbänder zur Verfügung. Die Knoten in unserem Problem sind hier die Masten. Zwei Masten sind durch eine Kante verbunden, wenn ihre Sendebereiche sich überlappen. Man kann nun $k$ verschiedene Frequenzbänder wählen, wenn und nur wenn der entstehende Graph $k$-färbbar ist.

Eine andere Anwendung kommt aus dem Compilerbau: ein Stück Code, zum Beispiel eine Funktion, benötigt in der compilierten Version $n$ lokale Variable. Nicht alle werden zum gleichen Zeitpunkt benötigt. Wenn zum Beispiel initial_value nur am Anfang benötigt und final_result erst gegen Ende berechnet wird, dann kann der Compiler für beide ein Prozessorregister benötigen. Jetzt will man wissen, ob man alle lokalen Variablen in den $k$ Prozessorregistern ablegen kann; dies ist wiederum ein Färbbarkeitsproblem: die Knoten sind die lokalen Variablen; die Farben sind die $k$ Prozessorregister. Zwei lokale Variable var_1 und var_2 sind mit einer Kante verbunden, wenn die Codebereiche, in denen sie vorkommen, sich überlappen.

Überlegen wir uns einen Algorithmus für $k$-Färbbarkeit. Wenn uns nichts besseres einfällt, können wir ja alle $k^n$ möglichen Färbungen $c$ durchgehen und jede überprüfen. Am Besten geht das rekursiv. Hierfür haben wir eine partielle Färbung des Graphen, genauer gesagt eine Funktion $\chi_i : \{u_1, \dots, u_i\} \rightarrow \{1,\dots,k\}$.

  • Iteriere über alle Farben $c \in [k]$

  • Färbe versuchsweise $u_{i+1}$ mit Farbe $c$. Setze also $\chi_{i+1} := \chi_i \cup [u_{i+1} \mapsto c]$.

  • Falls kein Nachbar von $u_{i+1}$ bereits Farbe $c$ hat versuche, $\chi_{i+1}$ zu einer vollständigen Färbung zu erweitern. Tu dies rekursiv.

Hier ist mein Python-Code "demo_exponentialcoloring.py".

Den können Sie so wie er ist abspeichern und laufen lassen. Das Programm"exponentialcoloring.py" kann Graphen als Eingabe lesen und die Färbung ausgeben, falls sie denn existiert: 

$unzip reductions.zip$ cd reductions 
$ python -m graphcoloring.exponentialcoloring 3
3 3
1 2 
2 3 
1 3 
{1: 1, 2: 2, 3: 3}

Sie können natürlich direkt mit dem <-Operator Dateien auf die Eingabe umleiten: 

$ python -m graphcoloring.exponentialcoloring 3 < icpc-format-graphs/petersen.txt 
{1: 1, 2: 2, 3: 1, 4: 2, 5: 3, 6: 2, 7: 1, 8: 3, 9: 3, 10: 2}

Der Algorithmus in demo_exponentialcoloring.py und exponentialcoloring.py baut einen Rekursionsbaum der Tiefe $n$ auf, in welchem jeder innere Knoten maximal $k$ Kinder hat. Somit hat der Baum maximal

$$ \begin{align*} 1 + k + k^2 + \cdots + k^n \leq k^{n+1} \end{align*} $$

Knoten (Knoten im Sinne von Rekursionsaufrufe, nicht im Sinne von Knoten des Graphen $G$). Pro Knoten, also Aufruf, benötigt der Code $O(n)$ oder $O(n \log n)$ Schritte, je nach Implementierung (im Moment implementiere ich coloring als Dictionary, was strenggenommen $O(\log n)$ Schritte pro Query benötigt; mit einem Array wäre dies in $O(1)$ möglich). Wenn wir es auf einer Turingmaschine implementieren würden, wäre es auf jeden Fall ineffizienter; dennoch würden wir pro Aufruf nur $\poly(n)$ viele Schritte tätigen müssen. Daher:

Beobachtung 9.4.3 $k$-Colorability $\in \TIME\left(k^n \poly(n)\right)$.

Übungsaufgabe 9.4.1 Zeigen Sie, dass $k$-Colorability $\in \TIME\left((k-1)^n \poly(n)\right)$ gilt, also insbesondere $2$-Colorability $\in \textnormal{P}$.

Übungsaufgabe 9.4.2 Denken Sie sich ein Beispiel aus, für das exponentialcoloring.py sehr lange braucht. Versuchen Sie, es mit einem möglichst kleinen Graphn in die Knie zu zwingen.

Gültige Färbungen erkennen

Erst einmal ist es eine triviale Beobachtung: wenn uns jemand eine Färbung $c: V \rightarrow \{1,2,3\}$ vorlegt, dann können wir ganz leicht überprüfen, ob $c$ für $G$ eine gültige Färbung darstellt. Hier mein Pseudocode. 

def is_proper_3_coloring(graph, c):
    (V,E) = graph
    for (u,v) in E:
        if c[u] == c[v]:
            return False
        if c[u] not in [1,2,3] or c[v] not in [1,2,3]:
            return False
    return True

Der Algorithmus is_proper_3_coloring ist eine Zertifikatmaschine im Sinne von Definition 9.3.3. Falls das "Eingabewort" $G$ $3$-färbbar ist, dann gibt es ein Zertifikat, so dass is_proper_3_coloring(graph, c) akzeptiert (lies: True zurückgibt). Ist $G$ nicht $3$-färbbar, dann gibt is_proper_3_coloring(graph, c) für jedes $c$ False zurück, lehnt also ab.

Beobachtung 9.4.4 3-Colorability ist in NP.

Das obige Beispiel verdeutlicht die Essenz der Klasse NP: es ist nicht klar, wie wir einen effizienten Algorithmus für 3-Colorabilityschreiben können; aber überprüfen, ob eine gegebene Färbung eine 3-Färbung von $G$ ist, das ist einfach.
